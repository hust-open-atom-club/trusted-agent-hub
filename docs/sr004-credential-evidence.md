# SR-004 凭据证据与测试值分级

SR-004 按源码内容识别硬编码凭据，不使用 `test`、`mock`、`fake`、`example`、README 或文档路径白名单。格式命中不代表凭据仍然有效；扫描器不向服务商发送凭据验证请求。

## 分类与计分

| 分类 | 条件 | 严重度 / 单个根因扣分 | 人工复核 |
| --- | --- | --- | --- |
| `credential_format` | 私钥、含密码的连接串、GitHub / OpenAI / AWS / Google / DigitalOcean / Slack / JWT 格式 | high / 15 | 必须 |
| `suspected` | 敏感字段中至少 20 字符且 Shannon 熵 ≥ 3.5，或跨文件复用，或存在网络/配置写入迹象 | high / 15 | 必须 |
| `unknown` | 已发现敏感字面量，但证据不足以认定用途 | medium / 8 | 必须 |
| `placeholder` | 精确匹配内置占位值，例如 `YOUR_API_KEY_HERE` | info / 0 | 无其他风险时不要求 |
| `test_fixture` | 精确匹配内置固定测试值，并有以该字面值为预期结果的相等断言 | info / 0 | 无其他风险时不要求 |
| `example` | 精确匹配内置示例值 | info / 0 | 无其他风险时不要求 |

这沿用扫描通过率和 I2 的严重度权重；最终风险等级仍由现有评分模型综合计算。`high` 凭据命中继续进入既有危险类别判断。所有分类都保留 finding，info 只免扣分，不从报告删除。

明确凭据格式、高熵、跨文件复用和网络/配置写入证据优先于测试值规则。私钥、看起来像真实凭据的随机值不能通过在文件名或注释中添加 `fake` / `test` 被豁免。未知值不会被自动认定为良性。

精确集合与具名格式规则定义在 `scanners/risk_scanner/credentials.py` 中。没有用户可配置的路径豁免或宽泛正则白名单。增加固定测试值时，应同时提交精确值、理由及正反回归用例。

## 审计证据

每个 finding 的 `credential_evidence` 包含类型、匹配规则、分类、分类置信度、理由、脱敏关联指纹，以及带文件/行列、变量或字段名、使用迹象和脱敏上下文的 `matches`。

置信度表示分类证据强度，不表示凭据有效概率。网络使用、配置写入和断言识别是保守的静态语法/邻近上下文分析，并非完整跨函数数据流证明；用途无法确定时交由人工复核。

同一扫描中相同字面值只产生一个根因，重叠的格式规则不重复扣分。其他文件中再次出现该值也会关联，`occurrences.count` 保留暴露总数。沿用报告的 100 处位置上限，超出时明确标记 `truncated` 并保留总数；原本 info 的不完整证据升级为 unknown/medium，要求人工核查其余位置。

指纹使用扫描内随机密钥的 HMAC-SHA256，截取 128 位用于关联。密钥不持久化，报告不输出凭据前后缀、原文、Base64 或无盐密码散列。finding ID 由脱敏位置与规则生成，在归并、API、LLM 以及相同源码的重复扫描中保持稳定；不同扫描的指纹不用于关联。

## 输出与复核

报告、API、源码预览及 LLM 上下文使用共享识别和脱敏逻辑。先在完整的扫描快照中识别字面值，再截取上下文，避免私钥截断或跨文件引用泄露。行号保留，原始行列仍指向扫描快照；脱敏后的字符串长度不代表原始列宽。

报告和 finding 按当前 `scan-report.schema.json` 的字段路径保护协议枚举与常量，包含嵌套命中、数组和 schema 引用。开放字符串类型的规则码、分类理由和新增限制原因使用 schema 的 `x-redaction-public-values` 显式声明可公开的固定值；其他值以及源码、包元数据仍脱敏。凭据值即使恰好是 `synthetic`、`dependency` 或其他协议词，也只隐藏其在描述、片段等自由文本中的出现，不改写协议字段。

跨文件字面量匹配在排序、转义和正则编译前限制为最多 512 个不同值、累计 65,536 个字符。超限时不编译部分列表：SR-004 中止细节分析，报告标记 `partial / inconclusive`，并记录 `credential_literal_limit_exceeded`；自由文本和源码预览保守隐藏，LLM 调用停止并要求人工复核。这样既限制编译开销，也避免漏掉列表末尾的凭据。扫描期间复用同一匹配器，重新扫描会重建；源码预览复用同一快照内容摘要对应的匹配器，沿用现有缓存的内存、淘汰和失效边界。

SR-004 不进入 LLM 语义降级流程；旧报告即使错误设置语义复核标记，也不能被 LLM 判为良性而改写分级。其他 finding 的 LLM 输入仍经过脱敏，并保留稳定 finding ID。人工应核对来源、用途、有效性和所有暴露位置，必要时撤销或轮换凭据；复核说明中不得粘贴原值。

规则异常日志仅记录规则编号和异常类型；错误报告也进行脱敏。服务端受访问控制的原始源码快照仍用于扫描和差异分析，不作为公开报告或模型输入。

静态规则不能证明未命中的内容不含秘密，例如运行时拼接、编码后的值或未进入扫描快照的文件。覆盖率不足和证据截断继续遵循现有人工复核策略。
